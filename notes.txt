==================================
Phase-2: Virtualization with Docker
==================================

Why we need Docker ?
- Imagine you are running your code on your laptop with a different programming version and another user is working on a different version...

Reason of failures:
- Using different programming version
- Using different version of libraries like scikit-learn, FastAPI
- Missing Python packages
- Different OS dependencies

Docker helps package your application code, runtime, dependencies and startup instructions into a standardized image

4 major requirements:
- Dockerfile - Set of instructions for packaging ML application
- Image - Packaged reusable application artifact
- Container - A running instance of the image
- Port Mapping - Makes the API inside the container accessible from your system

Docker Commands:
docker ps
Check running containers

docker ps -a
Check all active/non-active containers

docker build -t mlops-iris-image-cs .
-t = tag name = name of the image

docker run -d -p 8000:8000 --name mlops-cs-container mlops-iris-image-cs


==================================
Phase-3: Automated Testing and CI/CD with GitHUb actions
==================================

Our goal:
Whenever we push code on GitHub, the system should automatically run tests and build the Docker image. Later we will extend the same pipeline to publish the image and deploy it

1. Developer pushes the code
2. GitHub actions starts the workflow
3. Triggered by a push or pull request
4. Run tests and validate the model API behavior
5. Build Image and verify Docker packaging


Part-1: What are CI/CD ?
CI - Continuous Integration - Automatically validates the code changes through tests and build checks
CD - Continous Delivery - Keep changes ready to release, with production release potentially requiring approval
CD - Continuous Deployment - Automatically releases changes go production when all required checks pass


Automation Testing + Docker Build
