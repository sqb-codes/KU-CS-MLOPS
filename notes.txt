==================================
Phase-2: Virtualization with Docker
==================================

Why we need Docker ?
- Imagine you are running your code on your laptop with a different programming version and another user is working on a different version...

Reason of failures:
- Using different programming version
- Using different version of libraries like scikit-learn, FastAPI
- Missing Python packages
- Different OS dependencies

Docker helps package your application code, runtime, dependencies and startup instructions into a standardized image

4 major requirements:
- Dockerfile - Set of instructions for packaging ML application
- Image - Packaged reusable application artifact
- Container - A running instance of the image
- Port Mapping - Makes the API inside the container accessible from your system

Docker Commands:
docker ps
Check running containers

docker ps -a
Check all active/non-active containers

docker build -t mlops-iris-image-cs .
-t = tag name = name of the image

docker run -d -p 8000:8000 --name mlops-cs-container mlops-iris-image-cs

Part-1: What are CI/CD ?
CI - Continuous Integration - Automatically validates the code changes through tests and build checks
CD - Continous Delivery - Keep changes ready to release, with production release potentially requiring approval
CD - Continuous Deployment - Automatically releases changes go production when all required checks pass

Why we need MLFlow ?
- Imagine you train the same dataset ten times, changing the model parameters, dataset version
- Without experiment tracking we might end up with file names model_v1.joblib, model_v2.joblib and so on...
- MLFlow helps us maintain that record


4 Major Concepts:
- Experiment - Collection of related training runs
- Run - One execution of training with specific parameters and results
- Artifact - saved file produced by a run
- Model Registry - Managed catalog of registered models and their versions

Install MLFlow
pip install mlflow


Start MLFlow Tracking Server
mlflow server \
--backend-store-uri sqlite:///mlflow.db \
--host 127.0.0.1 \
--port 6001

Open browser and test URL:
http://127.0.0.1:6001


Evaluate and promote model vesions
- Right now FastAPI application loads a model from a local file
- This works for demo, but it becomes harder to manage when you have multiple model verions

Example:
Version-1: Initial model
Version-2: retrained model
Version-3: improved model

We can assign the alias champion to the model version we want our application to use


Load the champion model in FastAPI

Containerize MLFlow connected API

Restart mlflow server:
mlflow server \
--backend-store-uri sqlite:///mlflow.db \
--host 0.0.0.0 \
--port 6001 \
--allowed-hosts "host.docker.internal,host.docker.internal:6001"


Build the updated image:
docker build -t iris-ml-api-cs:v2 .


Start the container:
docker run -d \
--name iris-ml-api-container \
-p 8000:8000 \
-e MLFLOW_TRACKING_URI=http://host.docker.internal:6001 \
iris-ml-api-cs:v2
